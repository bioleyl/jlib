# jlib: notes for working on the code

jlib is a component library on Jadis (`@jadis/core` 1.6) and native Web Components, in atomic design, with a static
documentation site that shows and tests every component.

## Layout

- `src/`: the library. `atoms/` (one element: button, icon, input…), `molecules/` (a few atoms with one job: field,
  search, menu…), `organisms/` (a section with behaviour: dialog, data table, command palette…), `templates/`
  (layouts with slots). Pure helpers in `lib/` (tested in `tests/`), shared types in `types/`, shared CSS in
  `styles/`, the base classes in `base/`.
- `src/index.ts` and `src/all.ts` are **generated** by `npm run generate` from the component folders: never edit
  them by hand; run the script after adding a component.
- `site/`: the documentation site (Vite root `site/`, built with Jadis and jlib itself), on GitHub Pages under
  `/jlib/`. History routes: links use `pageHref('/route')`, files of `site/public` use `assetHref('file')` (never
  relative paths: the page's address has folders). The router follows clicks on links to the site's routes itself
  (`links: true`, shadow roots included; navigate in code with `router.gotoPath`, follow changes on `router.bus`);
  `services/navigation` only holds the links to `#` (the examples' placeholders), which it would show again.
  The build writes a copy of `index.html` for every route and a `404.html`. Pages show through a `jl-page-outlet`
  (`main.ts`): the current one stays until the next has its data. The outlet runs along the top of the content,
  under the header (`--line-top`), so the room around a page is the page's (`jl-page-outlet > *` in global.css). A component's page is made from
  `site/src/docs/components/<tag>.doc.ts`, loaded when the page opens (`import.meta.glob`, no registry to edit);
  the navigation, the search and the lists read `site/src/generated/components.json`, which `npm run generate`
  writes from the doc pages, so run it after adding one or changing a name or summary. The same goes for the pattern
  pages (`patterns.json`). The design system's pages load when one opens too: the router takes classes, so
  `lazyPage()` stands for each in `router.ts`; their nav list is `docs/design-pages.ts`, apart from the data they
  draw (`docs/design.ts`). The site does not load every component: each of its modules gets a `define()` of the
  classes of the jl-* tags it writes (`scripts/define-written-tags.ts`), so a component comes with the page that
  shows it. Write a tag whole (`<jl-table`, `'jl-button'`): one put together in code (`'jl-' + name`) is not seen,
  and the e2e suite fails on the undefined tag.
  The **Changelog** page (`/changelog`) draws `CHANGELOG.md` as it is (`lib/changelog.ts`): headings, paragraphs
  and `- ` lists (a line indented under an item continues it), with `code`, **strong** and [links]; no other
  Markdown.
- `plugins/`: the skills for coding agents working on apps built on jlib, one per Claude Code plugin (the repository
  is their marketplace, `.claude-plugin/marketplace.json`, which skills.sh reads too; `install-skill.sh` installs them
  in any agent's folder; the site's `/vibe-coding` page tells people about the three ways).
  `jlib-official/skills/jlib-official/` is how any app uses jlib: a change to what apps do with it (a component apps
  should reach for, an API, a trap) updates its `SKILL.md` or the reference of the topic too.
  `syware-ux/skills/syware-ux/` is how SyWare's apps apply the UX patterns: a pattern that changes updates it too.
  Written as Jadis's `jadis-official` is: a short `SKILL.md` (the model, a complete example, named rules, where to look,
  a self-check), and references opened on demand. `jlib-official` depends on `jadis-official` (marketplace `jadis`,
  allowed in `allowCrossMarketplaceDependenciesOn`), `syware-ux` on `jlib-official`. Generated by `npm run generate`
  from the doc and pattern pages, loaded whole in Node (`scripts/doc-modules.mjs`, `scripts/skill-references.mjs`):
  `references/components.md` and `references/components/<tag>.md`, `references/patterns.md` and
  `references/patterns/<slug>.md`; never edit them. An installed plugin holds only its own folder: a skill links
  nothing outside it. Their versions, and the `@syware/jlib@<version>` their files name, follow the package's
  (`npm version` writes them; `tests/skill.test.ts` checks them, every link and anchor, the Agent Skills fields and
  the install script). A code block of a skill that is a whole file (its first line a comment naming its path) is
  meant to type-check against the library: check new ones in a scratch app.
- `scripts/shoot.mjs`: screenshots site pages and reports console errors (own Vite server and Chromium per run).

## Writing a component

- File `src/<level>/jl-<name>.tsx`, its CSS beside it in `jl-<name>.css`, class `Jl<Name>` extending `JlElement`
  (`JlFormControl` for what a form submits), `static readonly selector = 'jl-<name>'`, `Jl<Name>.register()` at the
  bottom. Styles: `css\`${BASE_STYLES}${styles}\`` (add `CONTROL_STYLES` for text-field frames, `FLOATING_STYLES`
  for what opens over the page).
- **Inputs are `useChange` fields bound to an attribute** (`{ attribute: 'icon-end' }`), so they work from HTML, from
  JSX and from code. Text, numbers and flags parse by default; enums use `parse: oneOf(VALUES, fallback)`; lists and
  objects use `parse: jsonOf(fallback)` (HTML writes them as JSON: `items='[{"label":"A"}]'`). Mirror state the CSS
  needs on the host with `this.reflect('variant', value)` and style it with `:host([variant="primary"])`.
- **Outputs are `useEvents`** with a detail: `press`, `change` (detail = the new value), `input`, `open`, `close`,
  `select`… They do not bubble. Native events that cross shadow roots (`input`, `click`, `keydown`, `focusin`, `drop`…) must
  not be re-emitted under the same name without `event.stopPropagation()` on the native one (see `jl-input`). In
  JSX, an `on…` prop listens to them, typed by the detail (`<JlButton onPress={…} />`, Jadis 1.6): name events in
  lower case, a single word, so the prop reads well.
- Child components are used **by class** in JSX (`<JlIcon name="x" />`, `<JlPopover>…</JlPopover>`: a class takes
  children) so bundlers keep them. A component imported only for its side effect is dropped by tree-shaking
  (`sideEffects` in package.json): when a template needs the tag for an attribute no input names (`attrs`, such as a
  `part`, which a class reference refuses), also write `define(JlPopover)` at module level.
- A form control of one line (`JlInput`, `JlNumberInput`, `JlDatePicker`, `JlSearch`; `JlCombobox` and `JlTagInput`
  when Enter chose or added nothing) calls `submitImplicitly(event)` of `JlFormControl` for an Enter it does not use:
  its native field, in the shadow root, belongs to no form, so the browser's implicit submission never reaches the
  page's.
- `onConnect` wires listeners with `this.on`, `events.register`, `onBus`; it can run several times (an element taken
  out and put back; since Jadis 1.6, one moved in the page stays connected and keeps its state). The first
  `slotchange` can fire before `onConnect`: draw slot-dependent state there too (see `jl-dialog`).
- `useRefs` finds a child component by its class when it is the one with that tag: `icon: ref(JlIcon)` (Jadis 1.4);
  among several, by its own selector: `close: ref<JlButton>('.close')`.
- Methods callable before the element connects use `this.whenRendered(() => …)`.
- Internals come from `elementInternals(this)` (`lib/internals.ts`; `JlFormControl` has its own), never
  `this.attachInternals()`: happy-dom, which renders pages on a server, has none, and gets inert ones.
- **Texts a component shows on its own** (a close button's hint, an aria-label, a validity message) are jlib's, in
  `src/lib/texts.ts`: `DEFAULT_TEXTS` in English, `texts-fr.ts` and `texts-de.ts` beside it. A component writes them
  with `jlText(key, params)` in its `protected drawTexts()`, which `JlElement` calls at every connection (template
  there, before the paint) and again when jlib's language changes; never in the template, drawn once. A text input
  that defaults to one of them defaults to `''` and shows `this.label.get() || jlText('…')`; an input holding a text
  whose placeholders the component fills itself takes `jlTemplate(key)`. A new text goes in the three languages: the
  types refuse a language without it.
- Don't name an input or method like an `HTMLElement` member (`title`, `hidden`, `role`, `remove`, `click`,
  `translate`, `setAttribute`…). `key` is reserved by the JSX runtime.
- `part` in JSX: `attrs={{ part: 'base' }}` (expose the main inner element as `base`).
- Every look comes from `src/styles/tokens.css` (`--jl-*`): no literal colours in components. Flat surfaces with
  lines; shadows only for what floats (menus, dialogs, toasts). Heights: `--jl-control-sm|md|lg`.
- Accessibility is part of the job: roles and `aria-*` on the inner elements, keyboard (arrows in lists, tabs and
  menus; Escape closes what floats; Enter/Space activate), focus rings come from `BASE_STYLES` (`:focus-visible`).
- What floats goes in the top layer: `popover="auto"` (light dismiss) or `"manual"`, class `floating`, placed with
  `followAnchor(anchor, floating, placement, signal)` from `lib/floating.ts` with an `AbortController` per opening.
- Icons are tree-shaken: the registry (`src/lib/icons.ts`) starts empty. A component registers the lucide icons it
  draws itself at module level (`registerIcons({ x: X })`, below its imports); names a page writes (`icon="plus"`)
  are the page's to register, one by one or with `COMMON_ICONS` (`src/lib/icon-set.ts`, registered by `@syware/jlib/all`).
  An unregistered name draws a neutral mark and warns once; the e2e suite fails on that warning.
- Shared enums: `TONES`, `CONTROL_SIZES`.
- **A component that holds the page's values or records is typed by them**: a type parameter with the untyped form
  as default, `JlSelect<Value extends string = string>`, `JlTable<Row extends object = TableRow>`. A field of that
  type bound to an attribute brings its parser (`jsonOf`, `textOf`, `textListOf`: HTML is not checked against the
  type); a value read back from the DOM (`dataset.value`) is looked up in the options, not cast. Its type tests go
  in `tests/<name>.test-d.tsx` (checked by `npm run typecheck`, never run), and its doc gets a `typing`.

## Documenting a component

`site/src/docs/components/jl-<name>.doc.ts` exports `doc: ComponentDoc` (see `site/src/types/docs.types.ts` and
`jl-button.doc.ts`): summary, description, playground (starting attributes; a control per prop worth trying), every
prop (name, attribute, type, default as code, description), events, slots, methods, styling, and 3–6 examples. An
example is HTML rendered in the page (helper classes `row`, `stack`, `narrow`, `muted`), plus an optional typed
`setup(root)` and the `script` shown for it. A component typed by what it holds adds `typing`: what its type checks,
and two snippets, `site/src/docs/typing/<tag>.code.ts` and `.jsx.tsx`, imported with `?raw`. They are files that
TypeScript and Biome check; the page shows them without their lines ending in `// (not shown)` (a snippet's data, the
page's own functions), and a `// @ts-expect-error` line shows what the type refuses.

## UX patterns

The site's **UX patterns** (`/patterns`) are how every SyWare app behaves: navigation, page layout, lists, actions,
forms, states, feedback, confirmations, status, search, phones, accounts, and a checklist. One file per page in
`site/src/docs/patterns/<slug>.ts` (its `path` is `/patterns/<slug>`), written with the helpers of
`docs/pattern-kit.ts`, exported as `pattern`, and listed in reading order in `PATTERN_SLUGS` of `docs/patterns.ts`
(then `npm run generate`). Text takes `code`, **strong** and [links](/route);
previews are HTML of `jl-*` tags. A component change that alters a pattern updates its page too, and the
`syware-ux` skill (its pattern references are generated: its `SKILL.md`, `applying.md` and `ux-mistakes.md` are
not).

## Checking a change

`npm run check` (generate --check, lint, types, unit tests), then `npm run test:e2e` (builds the site and opens
every page in Chromium: no console error, no undefined `jl-*` tag, no unregistered icon). Look at the pages:
`node scripts/shoot.mjs /components/<name> --out <dir> [--theme dark] [--width 390] [--full] [--eval "…"]`.

## Gotchas met so far

- Flex and grid items are blockified: an `inline-flex` host reads as `flex` inside a flex container.
- `JlElement.isConnected` is Jadis's own flag, true from the start of `connectedCallback`.
- Biome's `useSortedKeys` reorders object keys: the route table keeps its order with a `biome-ignore` above it.
- The site's Vite root is `site/`: files above it need `server.fs.allow` (fonts, `src/`).
- A component's CSS is imported with `?inline` (as Jadis's template does), never `?raw`: Vite minifies `?inline` CSS
  in a build, and leaves `?raw` text as written, comments included, where no bundler can minify it. The library's
  build keeps its code unminified for the apps' bundlers but sets `cssMinify`, so its CSS is minified too. What the
  CSS says at run time is its minified form: nothing may read its comments.
- Document stylesheets don't reach shadow roots: examples render inside the component page's shadow root, which
  holds `EXAMPLE_STYLES`; `data-theme` on an element inside a shadow root needs `TOKEN_STYLES` in that root.
- Reflect an input's attribute only from that input's own callback. At connection the attribute callbacks run in
  field order: an earlier field's render that calls `reflect('selected', false)` erases the attribute before the
  `selected` callback reads it. Give derived host state its own name (`clickable`, `direction`).
- `formDisabledCallback` also fires for the control's own `disabled` attribute, possibly before render: keep the
  form's state apart and draw it with `whenRendered` (see `jl-input`).
- `this.on()` is typed for HTMLElement targets: for `document`, `window` or a `MediaQueryList`, use
  `addEventListener(…, { signal: this.killSignal })`.
- A JSX expression is typed as a plain element: cast it to its class to use its inputs
  (`(<JlSwitch />) as JlSwitch`).
- `useRefs` only holds HTML elements: keep SVG nodes in a private holder object.
- A cached `<img>` can fire `load` before `onConnect`: wire `onLoad`/`onError` in the template.
- A `<slot>` in a grid container makes every slotted node its own grid item: wrap the label and slot in a span.
- Biome's `useNamingConvention` flags `KeyboardEvent.key` names (`ArrowDown`) as object keys: use a `Map`.
- Implicit grid columns grow to their widest content: page grids use `grid-template-columns: minmax(0, 1fr)`, and
  a sideways scroller inside a component gets `contain: inline-size`, or phones scroll sideways.
- Re-showing a popover restarts the CSS animations inside it: use WAAPI for timers and enter animations there.
- A size container (`container-type: inline-size`) is the containing block of what is `position: fixed` inside
  it, slotted content included: a component that holds a page's content adapts with media queries (see `jl-page`).
- A `jl-button` with an `href` has two `part="base"` elements and hides the unused one: look for the visible one
  (`accessibleTarget` in `lib/trigger.ts`).
- Light dismiss closes a `popover="auto"` on pointerdown, before the trigger's click: read the open state on
  pointerdown or the click reopens it.
- `setFormValue(FormData)` uses the entries' own names: write them again when `name` changes.
- `::details-content` is not matched by `*`: give it `box-sizing: inherit` inside details.
- Link to light-DOM elements from a shadow root with element reflection (`ariaControlsElements`): ids cannot cross.
- The shoot script's Vite server reloads when files change: an `--eval` failing with "Execution context was
  destroyed" just needs a rerun.
- The SyWare logo SVGs in `site/public/` are the designer's paths, cropped. Shown small (under 64px), the site uses
  the PNGs that `node scripts/logo-png.mjs` renders from them (`site-logo`): the browser's smoothing filter blends
  about a quarter more edge pixels than the vector drawn at size, which on a standard screen shows steps.
- The package is `@syware/jlib` on npm (the bare name `jlib` belongs to someone else): docs and the site import it by
  that name (an alias to `src/` in development). `npm publish` runs the checks (`prepublishOnly`) and builds the
  library (`prepack`); the **Publish to npm** workflow (`.github/workflows/publish.yml`), started by hand for a
  pushed version tag (pushing the tag starts nothing), stages the version on npm and creates the GitHub release; a
  maintainer approves it (`npm stage approve`, with 2FA) to make it public. The whole procedure is in RELEASING.md.
- Biome leaves JSON files alone (not in its includes, JSON formatter and linter off): npm writes package.json and the
  lockfile in its own layout (`npm version`, `npm install x`), which Biome's formatter used to refuse.
